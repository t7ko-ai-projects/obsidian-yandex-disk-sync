# Ежедневные снимки хранилища

Только desktop. Включается переключателем «Ежедневные снимки» в настройках
(по умолчанию выключено). Снимки хранятся локально в папке плагина
(`<configDir>/plugins/<id>/snapshots/`), которая защищена от синхронизации, и никогда
не отправляются на Яндекс Диск. Это не замена резервной копии: см. [BACKUP.md](BACKUP.md).

## Что и когда сохраняется

- Через минуту после запуска и затем каждые 30 минут проверяется, есть ли снимок за
  текущую локальную дату. Если нет и переключатель включён, делается снимок. Команда
  «Сделать снимок хранилища сейчас» добавляет ещё один.
- В снимок входят все файлы хранилища, включая скрытые папки. Исключена папка самого
  плагина: там лежат токен и пароль шифрования.
- Содержимое адресуется SHA-256 (`blobs/<xx>/<sha256>`), одинаковые файлы хранятся один
  раз. Снимок описывает манифест `manifests/<id>.json`. Блоб и манифест пишутся во
  временный файл и переименовываются; манифест создаётся только после всех блобов,
  поэтому сбой оставляет самое большее неиспользуемые блобы.
- Файл, который не удалось прочитать, отменяет весь снимок: снимка с тихо пропущенными
  файлами не бывает. Файл с прежними размером и mtime не перечитывается.

## Сводка изменений

После нового ежедневного снимка открывается сводка относительно предыдущего снимка
(при пропущенных днях это последний существующий): добавлено, изменено, удалено,
перемещено (то же содержимое по новому пути). Клик по файлу показывает построчный diff;
для двоичных или больших файлов показываются размеры. «Восстановить копию» сохраняет
версию из снимка рядом с оригиналом как `имя (snapshot ГГГГ-ММ-ДД).расширение`, ничего
не перезаписывая. Команда «Показать изменения с последнего снимка» сравнивает снимок с
текущим хранилищем; в окне можно выбрать любую пару снимков.

## Хранение: 7 ежедневных и 3 недельных

`selectSnapshotsToKeep` (`src/snapshots/retention.ts`) пересчитывает набор только по
списку существующих снимков, поэтому пропущенные дни и запуски ничего не ломают.

1. Из нескольких снимков одной даты остаётся самый новый.
2. Ежедневные: 7 самых свежих дат, у которых есть снимок (не 7 календарных дней).
3. Недельные: среди остальных снимков по ISO-неделям (с понедельника) берётся самый
   новый снимок недели, для 3 самых свежих таких недель.

Самый новый снимок всегда сохраняется; повторное применение политики ничего не меняет.
После долгого перерыва остаются самые свежие снимки, а не пустой календарный период.

После обрезки блобы, на которые не ссылается ни один манифест, удаляются, но не младше
часа. Если хотя бы один манифест нечитаем, ни обрезка, ни сборка мусора не выполняются.

Проверки: `tests/snapshots.test.ts`. Работа в самом Obsidian не проверена автоматическими
тестами.
